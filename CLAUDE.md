# Front-desk MCP adapter (voice agent tools)

Three MCP tools for calling applications, consuming Manoj's operational service over HTTPS. This repository
owns only the adapter: `services/mcp`. Manoj owns the operational API (directory, live board,
slots, appointments, call summaries; pinned contract in `docs/handover/mcp-only/contracts/`).
The voice team owns knowledge, symptom routing and emergency decisions through Stratum's separate
ContextForge registration. Plan and target: `docs/handover/mcp-only/`.
Implementation evidence: `docs/handover/mcp-only/implementation/`.

## Commands
- Fast (no processes), run after every change: `make test-fast`
- Everything a reviewer runs on a clean checkout: `./scripts/test.sh` (lint, hermetic suites, process e2e, package and image build); CI runs it
- Process e2e only: `make test-e2e`; walk the tools: `make demo`; latency: `make bench`
- Tool surface: `make schema` must equal `services/mcp/tests/contracts/mcp-tools.snapshot.json`; bump `prompt.SCHEMA_VERSION` and regenerate when it changes
- Local stack against the operational development stub: `cp .env.example .env && make up`
- Environments: `eval "$(scripts/env.sh mock|live)"` is the one place an owner endpoint is written (`deploy/environments/*.env`, non-secret); it feeds deploy, the external gates and the bench. `live` names Manoj's base URL and the canary app `mcp-demo-hospital-canary` (release gates are in `docs/handover/mcp-only/PLAN.md`)
- Deploy: `deploy/azure/deploy.sh rollouts/<id> --profile live [--dry-run]` (profile names subscription `4e1c…` and `healthcare-rg`; the script never creates or defaults a resource group; `mock` can only dry-run)

## Rules the code will not tell you
- No backend scheduling, slot-allocation, capacity, interpretation, knowledge or clinical engine; no database, queue or local fallback backend. The adapter validates, authenticates, forwards trusted context, applies deadlines, maps contracted schedule facts through the approved availability policy and composes contracted reads.
- Trusted context (`X-Call-Id`, `X-Caller-Number`, `X-Caller-Verification`, `X-Operation-Id`, `X-Call-Started-At`) comes only from request headers. All three tools require the gateway bearer. Never from tool arguments.
- All three tools call only Manoj. Knowledge and emergency journeys belong to the voice platform through Stratum, outside this adapter. No optional routing gate, transcript header, local classifier or fallback. Voice-agent behaviour, prompts, guardrails and SDK integration belong to the voice team; the published interface is docs/handover/VOICE-TEAM.md. reasonVerbatim is forwarded to Manoj without interpretation.
- Schedule facts map through one pure `availability_policy.py` and one shared `schedule_reader.py`; owner `status` and MCP `decision` remain distinct. MCP consumes owner capacity facts and never computes capacity (K-1). Today a block is bookable only until it ends (K-2).
- AVAILABILITY for a selected doctor always reads `/slots` in parallel with existing reads; `SlotPlan.enabled` decides applicability. Department AVAILABILITY uses cached `/capabilities`, never a slots fan-out; slot-enabled matches are DOCTORS_MATCHED until a doctor is selected. WORKING_HOURS reads neither board nor slots. Only today reads the board; future slot reads supplement usual schedules.
- On-call AVAILABILITY follows ordinary policy only with confirmed IN/LATE plus either a usable window (both bounds, not ended) or an open bookable block. CANCELLED is NOT_AVAILABLE; otherwise HANDOFF_REQUIRED/TRANSFER_DESK, reason ON_CALL_DOCTOR, never callback (D-8).
- Single-doctor on-call WORKING_HOURS always returns HANDOFF_REQUIRED/TRANSFER_DESK, reason ON_CALL_DOCTOR: hours queries do not read confirmation data (D-8).
- UNKNOWN means callback for ordinary doctors in the selected scope; a session's label is evidence (D-6/D-7). CANCELLED is unavailable. Without slots, a supplied passed end is unavailable and today's NOT_CONFIRMED requires callback; with slots an open bookable block can permit a request. Failed reads are failures, not UNKNOWN; unreadable `/slots` or `/capabilities` means COULD_NOT_CHECK/COULD_NOT_RECORD, never unavailability (K-8).
- CREATE requires doctorId; RESCHEDULE derives the doctor from the appointment under the booking mobile. Department writes are absent. With slots enabled, chosen time is required: INVALID_REQUEST/ASK_WHICH_TIME and no write if absent. Optional `session` must match the containing session's normalized label and is never forwarded to Manoj. Without slots, mixed decisions require a choice; equal decisions permit a day-level request. A specific time in a bookable session with no end time produces HANDOFF_REQUIRED/TIME_NOT_VERIFIABLE, no write; no end is invented.
- Every appointment output includes nullable `slotTime` and boolean `slotMoved` (default false; false for LIST/CANCEL). Successful slot-aware CREATE/RESCHEDULE returns the recorded block start in `slotTime`; `slotMoved` is true only when the owner's returned time differs from the chosen block's start, not merely from the caller's time (K-7/D-3).
- CREATE and RESCHEDULE return NOTED, never confirmed (the nested appointment retains the owner's status). Writes need callerConfirmed, call id and operation id; the body remains frozen and keyed by sha256(tenant|call|action|operation). Booking uncertainty remains UNCERTAIN; summary uncertainty remains NOT_CONFIRMED. One same-key retry at most, within the invocation deadline; refresh only on 401.
- Single-doctor WORKING_HOURS with an empty regular schedule keeps the full callback result. A doctor with hours returns PRESENT_WORKING_HOURS; bookableFound is always zero for hours-only queries. Department hours keep on-call facts within the cap. Sessions crossing midnight are unsupported.
- Callback metadata is reason plus summaryOutcome=CALLBACK_NOTED. MCP creates no callback task or telephone transfer. Summary text may include the name, date, session and callback reason; their presence is not enforced by the summary service.
- LIST/CANCEL/RESCHEDULE are scoped to the supplied valid ten-digit patientMobile. Absent/blank uses the verified calling number under the configured country rule and accepted verification set; invalid explicit input never falls back. Missing/invalid booking mobile joins field validation before any owner call. The voice agent alone checks the patient's name, withholds records until a match and selects the family member; MCP does not verify entitlement to the mobile or perform name checks. No arbitrary prefix stripping.
- `record_call_summary` is LLM-callable with the same gateway bearer as the other two tools. Exact whole-call summaryText is required, nonblank and at most 500 characters; no text composition or truncation. Call ID and start time come from headers. The first accepted summary is final; same-call owner 200 means ALREADY_SAVED, even with a different payload. Summaries send no Idempotency-Key and no duration; MCP stays stateless.
- Results never carry caller numbers, reasons, raw upstream error prose or secrets; LOG-1 excludes private values and patient names from logs through one JSON handler, unfilled library templates, exact permitted adapter fields and route templates, keeps only exception types/frames, masks unexpected tool errors, and retains syntax-checked callId/summaryId for correlation. Two documented exceptions in results: the `patientName` of appointments under the supplied booking mobile (for the voice agent's name check; entitlement to that mobile is not verified) and the desk-authored board `note` (≤200 chars, written for callers). Request-URL loggers stay at WARNING.
- Contract changes are reviewed changes: the pinned snapshot, its hash, the overlay and `contract.py` literals are asserted by tests. Stubs (`services/mcp/dev/`) are fixtures, never engines; production refuses stub/mock hosts.
- Documentation or review approval is never deployment readiness: merge, live owner checks and deployment each need Garima's separate approval, against the release gates in `docs/handover/mcp-only/PLAN.md` (decisions in `docs/DECISIONS.md`). The published schema changes only through a reviewed `SCHEMA_VERSION` bump (see Commands), and a released schema change needs a gateway/ContextForge and voice-consumer refresh.
- Domain words live in `packs/healthcare.json`; tenant identity (timezone, calling code, languages) in `rollouts/<id>/rollout.env` with no defaults.

- Read deadlines derive from VOICE_RESPONSE_BUDGET_SECONDS minus RESERVED_STAGE_SECONDS and GATEWAY_OVERHEAD_SECONDS (default 1.0 - 0.65 - 0.05 = 0.30 s). Explicit READ_DEADLINE_SECONDS must fit that share. Confirmed booking writes have their own WRITE_DEADLINE_SECONDS (default 3.0 s) and WRITE_EXCHANGE_TIMEOUT_SECONDS (1.0 s), including schedule reads, caller appointment lookup and any retry. Read and summary exchange caps default to their own totals; summaries retain 8.0/8.0. Each cap must fit its total; read <= write <= summary. Tune the six values in rollout.env and redeploy. Ceilings do not delay successful replies or prove latency; live measurement and voice-platform timeout confirmation remain deployment gates.

## Gotchas
- Don't `source` rollout.env; use `scripts/rollout-env.sh`.
- Test conftest strips every `Settings` field from the environment; pass overrides via `make_settings(...)`.
- The clients cap every exchange with `asyncio.timeout` (httpx timeouts are per phase); in-process stub tests rely on that, and `test_ops_client.py` has a real-TCP dribbling-server test.
- `serving()` resets sse-starlette's process-wide drain flag at start (T-5); keep that reset. Without it, a previous test server's shutdown cuts off later event-stream replies in the same process (T-4).
- Hermetic process and journey tests (in-process/local stubs) use fixed future dates and normal daytime slots, never wall-clock, overnight or all-day windows. Read-only smoke may query today; authorised live external journeys use owner-designated dates.
